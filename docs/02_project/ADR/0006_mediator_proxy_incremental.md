# ADR-0006 · Медиатор-прокси (инкрементальное переключение фронта)

**Статус:** Принят (ЭП3, шаг 1)
**Дата:** 2026-09-17
**Контекст:** wclock5 (панель, Flask :10405)

## Проблема

Клиент-медиатор (panel_mediator.js, ЭП3) при `changed` **выбрасывал**
полученные в ответе payload'ы и снова вызывал старые window-активаторы
(`updateWeatherData`, `drawWeatherChart`, `updateBatteryChart`), которые
**сами** ходят в `/api/weather|charts_data|battery` (fallback-рендер).
Плюс старые setInterval'ы (`index.js:367` weather 30 мин, `battery.js`,
`weather_chart.js:338` charts 60 c) не отключались. Итог: запросов **не
стало меньше** — добавился лишь `POST /api/data_mediator` раз в 60 c.

## Решение (ADR)

Медиатор — **прозрачный прокси с кэшем**, переключение фронта — по
секциям, по одной, с тестом и отключением старого вызова. План по
этапам, каждый закрывает ровно одну секцию:

1. **weather**
   - медиатор отдаёт в `changed.weather.payload` полный weather-блок
     (как `/api/weather`);
   - клиент рисует **из payload**, старый таймер `updateWeatherData`
     (index.js:367) глушится;
   - на сервере включается файловый кэш `weather_payload` на
     `REFRESH_WEATHER_MS` (60 c).
2. **charts_data**
   - симметрично: `changed.charts_data.payload` → `drawWeatherChart(payload)`,
     старый таймер `weather_chart.js:338` глушится.
3. **battery.history**
   - клиент шлёт `params: {battery.history: {device_id}}` (иначе читалка
     возвращает `_error device_id required`);
   - `changed.battery.history.payload` → `updateBatteryChart(payload)`,
     старый таймер battery.js глушится.

Принципы:

- **мой выбор: сейчас только шаг 1 (weather), остальные — после зелёного
  локального теста этого шага;**
- деплой шага — после локального e2e (test_client), прод — «пп -дп»,
  откат шага = вернуть клиентский URL на `/api/weather` (тривиален);
- кэш подключается только для конкретного вызова (шаг 1), не глобально.

## Альтернативы (рассмотрены)

- **A. «Полный самосинк» одной правкой** — клиент целиком рисует из
  медиатора, все старые таймеры гасятся разом. Риск: падение одного
  рендера ломает панель целиком; откат тяжёлый. Отклонено в пользу
  инкремента (ADR-0006).
- **B. Оставить дельту поверх (как сейчас)** — запросов не меньше,
  проблема не решается. Отклонено.

## Последствия

- Запросы: ~1 POST /api/data_mediator + 0…1 активация из changed на один
  интервал опроса (60 c) вместо N таймерных GET.
- Fallback /api/* остаётся живым (если медиатор упал — активаторы живы
  сами); это страховка, переключаем секции по одной.
- battery.history ждёт device_id — без него шаг 3 невозможен (будет
  `_error`), поэтому параметр добавляется на шаге 3.
