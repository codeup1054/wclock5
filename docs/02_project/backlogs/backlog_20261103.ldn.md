## Цели

### Цель №1 — Мультипортфельность: реестр источников ✅

**Проблема**: источники были захардкожены (`'tinkoff'`, `'finam'`) в графике,
баннере и настройках; добавление счёта = правки в 4 файлах + копия демона.

**Решение**:
- `static/js/invest_sources.js` — реестр `InvestSources` (`id, label, marker,
  colorKey, axis, enabled`): один источник = одна запись; `color(id)` берёт
  цвет из `ChartTheme`.
- `static/js/invest_chart.js` — Tinkoff/Finam считаются явно (свои оси/стек
  долей), остальные — циклом `extras` по реестру: своя ось (`y_<id>`) с
  диапазоном от первого ненулевого значения, пара рядов ₽/%, `periodSources`,
  `spanGaps:false`, `recomputePortfolioAxis` по осям из реестра.
- `static/js/invest_banner.js` — `SOURCE_META`/`SOURCE_ORDER` из реестра,
  `collectionEnabled(src)` → ключ `invest_collection_<id>_enabled`.
- `static/js/lib.js` — переключатели «Сбор данных через API» генерируются из
  реестра (Tinkoff, Finam, С5 TDIV, С3 TRND).
- `parsers/invest/sources.json` — реестр бэкенда (только имена env-переменных,
  без секретов).

### Цель №2 — Один демон на все счёта T-Invest ✅

**Проблема**: `tdiv_invest_daemon.py` был копией `tinkoff_invest_daemon.py`
(дублирование ~330 строк на каждый новый счёт).

**Решение**: `parsers/invest/account_invest_daemon.py` — универсальный демон:
источник из `INVEST_SOURCE`, имена токена/счёта/интервала из `sources.json`,
`source=<id>` в снапшотах, флаг сбора `invest_collection_<id>_enabled`.
`tdiv_invest_daemon.py` оставлен тонким шимом (`runpy` + `INVEST_SOURCE=tdiv`).
`docker-compose.yml` — сервисы `tdiv-invest-parser`, `trnd-invest-parser`
с `environment: INVEST_SOURCE=<id>`.

Проверка: `wclock5-tdiv-inv` пишет `source='tdiv'`, 2 позиции, 99 384 ₽.

### Цель №3 — Безопасные токены ✅

**Проблема**: токены вставлялись в чат/командную строку, попадали в историю
shell и в `ps`; смена счёта требовала ручной правки `.env`.

**Решение**: `sh/invest_tokens.py` — `add / list / check / remove`:
- ввод токена только `getpass` (без эха) или stdin, никогда аргументом;
- валидация у брокера (`GetAccounts`) и авто-выбор счёта;
- запись в `.env` (gitignore) c `chmod 600`, имена переменных `<ID>_TOKEN`,
  `<ID>_ACCOUNT_ID`, `<ID>_UPDATE_INTERVAL_SEC`;
- реестр `sources.json` без секретов; `list` показывает маску (`t.rs…rQ (len 88)`);
- `remove` чистит env-ключи и реестр (данные в БД остаются).

### Цель №8 — Читаемые метки счетов в таблице ✅

Первая колонка баннер-таблицы вместо одной буквы показывает
`буква брокера:инструмент` — крупнейший не-денежный инструмент счёта без
суффикса площадки (`TGLD@@RUSX` → `TGLD`):

```
T+F     итог по Tinkoff+Finam
F:TGLD  Finam      (F = Финам)
T:CNRU  Tinkoff    (T = Тинвест)
T:TDIV  С5 TDIV
T:TRND  С3 TRND
TGLD / XAU / USD / Brent / Gap — без изменений
```

Буква = **брокер**: `T` — Тинвест (все его счета), `F` — Финам.
Порядок строк и колонок легенды — `finam → tinkoff → tdiv → trnd` (порядок
реестра `invest_sources.js`).

Реализация: `topInstrument(positions, source)` в `invest_banner.js` (фильтр
денежных позиций, максимум по `value`, обрезка `@…`), полное имя счёта — в
`title` строки и ячейки; `marker` в реестре источников.

### Цель №9 — DPI-слайдер: заметное уменьшение шрифтов и линий ✅

**Симптом**: «DPI погоды» двигался, но график почти не менялся — эффект был
сглажен делением отклонения на 3 (`×0.75…×1.17` на диапазоне 0.5…3).

**Решение**: `chartFontScale(target)` в `lib.js` стал пропорциональным DPI:
`clamp(dpi/2, 0.4, 2)`. При dpi=2 — прежний вид (×1).

Проверка (погода): шрифты осей `9.6 → 36 px`, толщина линий `4 → 15 px`
при dpi 0.5 → 3. Инвест-график: толщина `0.35 → 2.1`, шрифт оси X `4.8 → 18`.
Механизм перерисовки не менялся (`weatherDpiChange` / `investDpiChange`
пересоздают график и перечитывают `chartDpiValue`).

### Цель №14 — Метки периода: вне графика, тикеры слева / портфели справа ✅

Метки начала и конца (значение + прирост %) больше не рисуются внутри поля:

- позиция по X — **вне графика**, с тем же отступом 6 px, что у подписей оси Y:
  тикеры — слева от `chartArea.left` (выравнивание вправо), портфели — справа

  они появлялись только после первого инкрементального обновления).

Замеры: правые метки `x = 1350…1480` при canvas 1483 — без обрезки; левые
`x = 4…103` (тикеры). Переполнения нет ни у одной метки.

### Цель №15 — Метки периода как бейджи + настройка шрифта ✅

- Метки начала/конца рисуются **бейджами**: фон — цвет показателя с
  прозрачностью **60%** (`rgba(...,0.6)`), текст **чёрный**, скругление от
  размера шрифта, паддинги фиксированные **0 по вертикали / 2 по горизонтали**
  (высота бейджа = размер шрифта, ширина = текст + 4 px).
- **Шрифт бейджей настраивается** в редакторе темы: группа **«Метки периода»**
  (`⚙ Параметры`), сразу под «Цвета тикеров» — токен темы
  `font.badge` (8…30 px, по умолчанию 16). Правка идёт через `ChartTheme`,
  поэтому сохраняется вместе с темой, попадает в профиль и перерисовывает
  график (`chartThemeChange`). Дубль `period_label_font` из «Настроек графика»
  убран.
- Бейдж не выходит за холст: `bx` зажимается в `[3, chart.width − bw − 3]`,
  иначе правый край панели обрезал «102 276 +0.44%» (С3 TRND).
  Проверка: все бейджи `right ≤ 1480` при canvas 1483, переполнений 0.
- `MIN_GAP` теперь зависит от шрифта (`fontSize + 6`), чтобы бейджи не
  наезжали друг на друга при увеличении.

### Цель №16 — Бейджи: начало слева, конец справа ✅

Метки разведены по сторонам независимо от оси показателя:

```
слева (chartArea.left − 6, выравнивание вправо):  99 384 · 101 941 · 13.78 · 4.176 · 84.61 · 96.74
```
