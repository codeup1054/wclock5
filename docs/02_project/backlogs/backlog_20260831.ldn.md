## Открытая задача (31.08, вечер) — график «не отображаются портфели» при выборе мелкого интервала
Симптом (классика wclock5:10405): клик interval-group «1M» при периоде по умолчанию
`-35 day` → `aggregateData` раздувает серию до ~50к точек (gap-fill по 1-минутным
слотам на весь период) → главный поток занят >30с → срабатывает таймер
`Timeout 30s, isUpdating reset`, событие виснет в `isUpdating` → «Update already
in progress, skipping» → портфели Тинькофф/Финам не отрисовываются. Сопутствующее:
`/api/invest/tickers?interval=minute&period=-35day` отдавал 9MB (49к точек/тикер).

### Фикс (применён на классике и в hft для паритета)
- **CHRT-FIX ✅ (H)** — `aggregateData`: кап `MAX_AGG_POINTS=3000` (равномерное
  прореживание с сохранением последней точки) после gap-fill. Нормальные комбо
  (период→интервал ≤168 точек) не меняются; патологическое minute/-35day
  49663→2922, fivemin/-35day 9933→2484.
- **CHRT-FIX ✅ (H)** — `/api/invest/tickers` (классика app.py) и
  `/api/hft/chart_tickers` (hft/app.py): кап `MAX_TICKER_POINTS=3000`
  деклиматированием массива prices (с сохранением first/last). 9MB→~0.9MB,
  49к точек → ~2900. Деплой: классика 10405 (scp+restart wclock5-app), hft 10406
  (scp+restart hft-app, cache-bust index.html `.3`→`.4`), MD5 OK, tickers live
  GDH6/TGLD@/XAU 2896/2896/2862, test_globals 25 ✅, node --check JS OK.
  Задача общая для wclock и hft (фикс применён в обоих). Правила и разбор —
  эпик `docs/02_project/epics/EPIC_chart_rendering.md` (GRD-01..05).
- **CHRT-FIX-2 ✅ (H)** — `y_pct` (нормированные `%`-ряды) схлопывался:
  при малом разбросе (портфель двинулся ~0.2% на minute/-6h) Chart.js
  auto-ось без min/max сворачивала диапазон, и линии `Tinkoff,%`/`Finam,%`
  выглядят горизонтальными, тогда как `₽`-линии (явный min/max) в порядке.
  Фикс: явный симметричный диапазон `y_pct` `min:-bound, max:+bound`
  (bound = max(|%|)*1.15, floor 0.2) в `updateInvestPlot` классики и hft.
  Деплой: классика scp (mtime), hft scp+restart+index `.4`→`.5`, MD5 OK,
  test_globals 25 ✅, node --check JS OK.
- **CHRT-SYNC ✅ (M)** — синхронизация `₽`-осей: `y_portfolio` (Tinkoff) и
  `y_finam` (Finam) теперь делят общий диапазон `max(max_T,max_F)` /
  `min(min_T,min_F)` + запас 10% (`buildScales`), чтобы абсолютные значения
  портфелей можно было сравнивать напрямую. Толщина `₽`-линий 2→0.7.
  Классика+в hft, деплой MD5 OK, node --check OK.
